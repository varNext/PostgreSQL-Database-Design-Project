Практические учебные работы по PostgreSQL

# Практическое задание №1
# Практическое задание связано с проектированием схемы базы данных для аналитики.
## Постановка задачи
Основная задача состоит в создании оптимизированной структуры БД, способной эффективно работать с большими объемами данных, поддерживать полнотекстовый поиск и секционирование таблиц. Результатом данного практического задания являются: скрипты создания базы данных, хранимая процедура (генератор) для ее заполнения, анализ плана выполнения запроса.

## Требования к БД
✓ Одна таблица (Item transportation) должна содержать не меньше 10 млн. записей. 
✓ Другая таблица (Shipped Item), связанная с первой, должна содержать не меньше 1 млн. записей.
✓ Остальные таблицы должны содержать по 5-10 записей.
✓ В одной из таблиц с количеством записей 10 млн. используется колонка Comment с человекочитаемым текстом (не псевдопоследовательность), по которой далее будет необходимо настроить полнотекстовый поиск. Объем выборки ~1000 слов.


## Особенности работы 1
• регистрация/активация расширения python в СУБД создается командой CREATE
• шаблон объявления функции/процедуры в PostgreSQL
CREATE FUNCTION имя_функции (аргументы)
RETURNS возвращаемый_тип
AS $$
 (Тело функции на PL/Python)
$$ LANGUAGE plpython3u;
Тело функции содержит просто скрипт на языке Python. Когда вызывается функция, её аргументы передаются в виде элементов списка args; именованные аргументы
также передаются скрипту Python как обычные переменные.
• нельзя использовать СУБД драйвер python psycopg2.
• генерация должна происходить прямо в процедуре/функции. Для оптимизации скорости все ограничения БД (первичные/внешние ключи, ограничения типа)
нужно добавлять в таблицы после окончания генерации. Сами строки для вставки генерировать нужно блоками (1000-100000). Если вставлять по одной строке, будет
долго из-за поддержки целостности.

# Практическое задание №2 
# Использование документно-ориентированных объектов типа Json
## Постановка задачи
PostgreSQL стала первой реляционной базой данных, поддерживающей слабоструктурированные данные. В PostgreSQL для этого используется JSON, который имеет два представления: json и jsonb. Для реализации эффективного механизма запросов к этим типам данных в Postgres также имеется тип jsonpath. Официально JSON появился в PostgreSQL в 2014 году. PostgreSQL с JSONB совмещает гибкость NoSQL, а также надёжность и богатство функциональности реляционных СУБД.

Требуется создать БД IMDB test, использующую стандартные атрибуты и атрибут jsonb. 
Для загрузки используется один файл actors.list.txt.

После создания БД требуется:
1. Составить 4-5 запросов с использованием api postgresql для jsonb:
– используя проверки на вхождение и существование jsonb;
– используя обращение по индексу к элементам jsonb;
– используя язык jsonpath;
– используя функции для типа jsonb.
2. Измерить время доступа к полю jsonb для каждой строчки (в виде таблицы или графика). Оценить влияние длины строки на скорость доступа (ожидается ступенька до 2kB, после линейная зависимость). Для этого следует измерить время чтения year первой роли актера
(explain analyze). Для точности оценки важно учитывать хранимую длину (jsonb хранится в сжатой форме). Как можно это влияние уменьшить?
3. Составить запрос на изменение year у первой роли актера. Сравнить изменение объема БД для актера с малым кол-вом ролей и актера с большим количеством ролей (toasted roles).
